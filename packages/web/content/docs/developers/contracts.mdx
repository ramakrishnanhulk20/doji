## LoanManager

Custody of veBTC positions, loans, auctions and settlement. Every state-changing function runs under one reentrancy lock.

### Borrower functions

| Function | Who may call | What it does |
| --- | --- | --- |
| `deposit(uint256 tokenId)` | the position's owner | Pulls a veBTC position after a single-token approval and records the caller as its borrower. |
| `lockAndDeposit(uint256 amount, uint256 lockDuration)` | anyone | Locks the caller's BTC as a new veBTC position minted straight to LoanManager. Pausable. |
| `lockAndBorrow(uint256 amount, uint256 lockDuration, uint64 maturity, uint256[] offerIds, uint128[] amounts, uint16 maxAprBps)` | anyone | Locks and borrows in one transaction, with every borrow check. Pausable. |
| `borrow(uint256 tokenId, uint64 maturity, uint256[] offerIds, uint128[] amounts, uint16 maxAprBps)` | the borrower | Borrows MUSD from the listed offers against a held position with no open loan. Pausable. |
| `repay(uint256 tokenId, uint256 amount)` | anyone | Pays down a loan, at most what is owed. The last payment closes the loan and any auction. Never paused. |
| `roll(uint256 tokenId, uint64 newMaturity, uint256[] offerIds, uint128[] amounts, uint16 maxAprBps, uint256 maxTopUp)` | the borrower | Moves an active, on-time loan to a later Thursday and repays the old date in full. Never paused, but pays nothing out while borrows are paused. |
| `withdrawCollateral(uint256 tokenId)` | the borrower | Sends a position with no open loan back to its borrower. |
| `vote(uint256 tokenId, address[] pools, uint256[] weights)` | the borrower | Casts the position's PoolsVoter vote. The loan must be on time and safe, and a normal lock cannot vote in its last week. |
| `resetVotes(uint256 tokenId)` | the borrower | Clears the position's PoolsVoter vote. |
| `claimRewards(uint256 tokenId, address[] gauges, address[][] feeTokens, address[][] bribeTokens)` | the borrower, or the reward operator the borrower named | Claims pool fees and incentives from registered gauges and pays the measured increase of each listed token to the caller. Wave 2: a token passes when the gauge's own fee or incentive contract lists it (`isReward`, F36), so a pool's own tokens, MUSD and BTC included, pass whether or not PoolsVoter whitelists them. The 20 October pair accepts only PoolsVoter's whitelisted tokens, and Mezo's testnet whitelists neither MUSD nor BTC. |
| `setRewardOperator(uint256 tokenId, address operator)` | the borrower | Wave 2. Names the one other address that may call `claimRewards` for this position and receive what it claims, such as PayDown, or clears it with the zero address. Naming LoanManager reverts `InvalidOperator`. The operator can do nothing else, the borrower can still claim, clear and repay, and the operator is deleted with the position record. Never paused. |
| `claimRebase(uint256 tokenId)` | the borrower | Claims from the veBTC fee distributor. BTC from an expired lock is credited to the borrower's claimable. |
| `extendLock(uint256 tokenId, uint256 lockDuration)` | the borrower | Pushes the lock's end out with veBTC's `increaseUnlockTime`. The loan must be on time and safe. |

On the Wave 2 pair `claimRewards` and `setRewardOperator` also run while the loan is in auction, so what the position earned stays with its borrower and a harvest can still repay (audit L-01, F37). `vote`, `resetVotes`, `claimRebase` and `extendLock` never run in an auction. On the 20 October pair none of the pass-throughs runs in an auction.

## CreditMarkets

Offers, one market per Thursday, and the ERC-1155 credit units whose token id is the Thursday. Every state-changing function runs under one reentrancy lock.

### Lender and holder functions

| Function | Who may call | What it does |
| --- | --- | --- |
| `postOffer(uint64 maturity, uint16 aprBps, uint128 amount)` | anyone | Escrows exactly `amount` MUSD as a fixed-rate offer for a valid Thursday within the longest term. Pausable. |
| `postParkedOffer(uint64 maturity, uint16 aprBps, uint128 amount)` | anyone | Wave 2. ## PassThrough

An external library that holds LoanManager's calls into Mezo's voters: `castVote`, `forwardRewards` and `clearForSettle`. It exists only to keep LoanManager under the contract size limit. LoanManager runs it with `delegatecall`, after its own borrower and custody checks and under its reentrancy lock. It keeps no state, and its events and errors are LoanManager's own, so logs carry LoanManager's address. Each pair links its own copy. The Wave 2 copy checks every listed reward token with `isReward` on the reward contract PoolsVoter registered for the gauge, measures each distinct token once, and pays the caller.

## PayDown (Wave 2)

Turns a position's pool rewards into repayment of its loan. A borrower opts in by naming PayDown as the position's reward operator in LoanManager. PayDown keeps no balance between calls, and every function that moves tokens runs under one reentrancy lock.

### Functions

| Function | Who may call | What it does |
| --- | --- | --- |
| `harvest(uint256 tokenId, address[] gauges, address[][] feeTokens, address[][] bribeTokens)` | anyone; the keeper does it weekly | Reads the borrower from LoanManager, measures PayDown's balance of MUSD and every listed token, claims through `LoanManager.claimRewards` as the operator, and uses only each measured increase. With an open loan: MUSD gained counts toward the repay; BTC gained is sold only as far as the debt still needs, on the BTC to MUSD volatile route of the Router's default factory, with the oracle floor (BTC sold x price x (10,000 - `slippageBps`) / 10,000) handed to the Router and checked again against the MUSD measured arriving; then the smaller of the MUSD gained and `owedOf` is repaid. Everything else goes to the borrower in the same call. With no open loan nothing is sold. The price is read only when BTC must be sold. Works during an auction, and a harvest that clears the debt ends it. |
| `harvestAndSwap(uint256 tokenId, address[] gauges, address[][] feeTokens, address[][] bribeTokens, Swap[] swaps)` | the borrower | The same, and it also sells the reward tokens the borrower lists, other than MUSD and BTC: at most 8, each on a route of 1 to 3 hops from the token to MUSD, each at the borrower's own minimum, which the MUSD measured arriving must reach. The swaps run before the BTC sale, so their MUSD shrinks the BTC sold. |
| `setSlippageBps(uint16 newSlippageBps)` | owner | The discount to the oracle price a BTC sale may accept: 100 (1%) at deployment, at most `MAX_SLIPPAGE_BPS` 300 (3%). |
| `setGuardian(address newGuardian)` | owner | Sets the guardian. |
| `setPaused(bool newPaused)` | guardian or owner to pause, owner to resume | Pauses `harvest` and `harvestAndSwap` only. Nothing in LoanManager changes: the borrower's own claim, operator clear and repay keep working. |
| `rescueToken(address token, address to, uint256 amount)` | owner | Moves tokens PayDown holds outside a harvest. A harvest keeps nothing, so anything held at rest is a stray credited to nobody. Under the reentrancy lock, so it can never run inside a harvest. |
| `transferOwnership(address newOwner)`, `acceptOwnership()` | owner, then the new owner | Two-step ownership transfer. |
| `renounceOwnership()` | nobody | Always reverts `RenounceDisabled`. |

### Views

| Function | Returns |
| --- | --- |
| `slippageBps()`, `paused()`, `guardian()`, `owner()`, `pendingOwner()` | The current settings and roles. |
| `loanManager()`, `router()`, `factory()`, `musd()`, `btc()`, `priceFeed()` | Fixed at deployment. MUSD, BTC and the price feed are read from LoanManager, the factory from the Router. |

## Faucet

One starter kit per wallet, for the [quests](/docs/getting-started/quests). It holds test tokens only, owed to nobody. No Doji contract reads it, so it can touch no loan, offer or unit. It had the reviewer's threat pass and the test suite, not a separate audit.

| Setting | Value |
| --- | --- |
| Faucet | [0xCd80D2ef1D47db5c5bc784DE5Ac7a980F8E97BAa](https://explorer.test.mezo.org/address/0xCd80D2ef1D47db5c5bc784DE5Ac7a980F8E97BAa), verified |
| Relayer, the one address that can call `claim` | [0x837Fbb9E11f47293fF31F4F79AD5D5E3EC29aEbA](https://explorer.test.mezo.org/address/0x837Fbb9E11f47293fF31F4F79AD5D5E3EC29aEbA) |
| Owner | The deployer, `0xd338Ad588D6c3aE127FD5eEC6843A468d3a7aa6e` |
| Deployed | 5 November 2026, block 16,590,424 |
| Record | [deployments/31611-faucet.json](https://github.com/ramakrishnanhulk20/doji/blob/main/packages/contracts/deployments/31611-faucet.json) |
| Kit | 0.001 test BTC and 25 test MUSD |
| Daily limit | 40 claims each UTC day |

### The rules

- One whole kit, to one address, once ever. A claim that cannot pay in full reverts and leaves the address free to try again (C54).
- Only the relayer can claim, so a wallet with no gas can get its first gas. `POST /api/faucet` asks the relayer to send a claim after a Cloudflare Turnstile check and a simulation. The chain does not see that check: only the relayer key stands behind it (C59 to C65).
- Claims are released evenly through each UTC day: the limit times the seconds so far, divided by a day, plus one, up to the limit. Unused ones carry over within that day, and each new UTC day starts again, so a sweep at midnight takes one kit (C57).
- The BTC payment forwards a fixed 50,000 gas, enough for a heavy smart wallet's receive, and copies no return data, so a hostile recipient has a fixed price. There is no is-it-a-contract check (C55).
- BTC is read one way, the Faucet's native balance, because native BTC and Mezo's BTC ERC-20 are the same coins. BTC or MUSD sent in is funding, credited to nobody (C58).

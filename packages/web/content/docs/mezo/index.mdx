Doji is built on Mezo's own pieces. The collateral is veBTC, the loan is MUSD, the price is MUSD's own price feed, and the borrower's votes and fees keep flowing through Mezo's voters and fee distributor. Take Mezo away and nothing is left.

## Every Mezo contract Doji calls

Testnet addresses are the ones in Doji's [deployment record](https://github.com/ramakrishnanhulk20/doji/blob/main/packages/contracts/deployments/31611.json). Mainnet addresses are Mezo's live mainnet contracts, checked on Mezo's explorer and chain, and the [fork tests](/docs/developers/run-the-proof) run Doji against them.

Doji does not call BoostVoter. A mainnet fork test (test C in [PassThroughFork.t.sol](https://github.com/ramakrishnanhulk20/doji/blob/main/packages/contracts/test/fork/PassThroughFork.t.sol)) checks that a BoostVoter vote leaves veBTC's voted flag alone, so it can never block a settle.

## Mezo rules Doji is built around

- Weekly epochs turn on Thursday 00:00 UTC, and veBTC lock ends fall on the same boundaries. That is why every Doji loan is due on a Thursday.
- A veBTC lock lasts at most 28 days, so no Doji loan runs longer than 4 weeks, permanent lock or not.
- Votes persist from epoch to epoch. Each position gets one vote or reset per epoch, none in an epoch's first hour, and a lock with a standing vote cannot be withdrawn. Doji blocks votes in a normal lock's last week, so the reset settle needs is always possible.
- `locked()` returns three words on testnet's older veBTC and four on mainnet (with a boost). One reader decodes it for the chain it was deployed on and refuses anything else.

## What Doji never touches

LoanManager acts on positions only through the calls in the table. It gives no veBTC approval or approval-for-all, has no generic call or multicall, never merges, splits or makes a lock permanent, and never swaps on a DEX. It accepts no meta-transactions and has no forwarder: every call acts for the address that sent it.

<Callout type="warn">
On 5 October 2026 an attacker moved 37 veBTC positions on Mezo mainnet through a flaw in how a trusted forwarder (Mezo's meta-transaction path) passed on the sender. Mezo has since turned meta-transactions on veBTC off, and live veBTC's `forwarder()` returns the zero address ([Mezo's incident report](https://mezo.org/blog/incident-report-october-5-2026)). A contract that holds many positions concentrates exactly that kind of risk, which is why custody comes first in Doji's [threat model](/docs/security). One non-goal remains and is stated: Mezo's PoolsVoter still trusts an ERC-2771 forwarder. A flaw there could act as LoanManager on PoolsVoter (vote, reset, claim). Rewards would still land with LoanManager, and the worst outcome is a delayed settle.
</Callout>

## Testnet and mainnet

Doji is deployed on Mezo testnet only, and its deploy script refuses mainnet. Testnet runs an older veBTC: three-word `locked()`, no veMEZO boost and no secondary voters. Mainnet behaviour is proven by fork tests that run Doji against real mainnet positions, the real voters, MUSD and the fee distributor. See [Run the proof yourself](/docs/developers/run-the-proof).

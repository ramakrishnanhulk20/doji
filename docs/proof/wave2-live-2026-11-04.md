## The first harvests, 5 November 2026

The epoch ended on Thu 5 Nov 00:00 UTC, so the incentives became claimable. Two open loans had pay-down on: #411 from the section above, and #412, which votes for the MUSD/mT pool only. Of those two harvests, one went through and one was refused.

Other voters on these pools shared the incentives, so #411 and #412 earned only their share:

Under "Other rewards waiting" mT was ticked, as it is by default, and its row read 0.0268 mT, "at least 0.2052 MUSD". The script pressed "Pay down and sell", and the Done line read "Harvested: 1.5899 MUSD went to loan #412. Sold 0.0268 mT for 0.2073 MUSD."

PayDown's `RewardSwapped` event shows 26805481157318754 mT sold for 207308580731477064 MUSD, and its `Harvested` event shows the borrower as caller, 1589907820513553901 MUSD repaid and no BTC sold. The repayment is exactly the 1382599239782076837 MUSD claimed plus the sale. `owedOf(412)` fell by exactly that amount, from 10012502568493150685 to 8422594747979596784, and PayDown holds no MUSD afterwards. The sale minimum in the transaction, 205235494924162293, reads 0.2052 as on the screen and is exactly 99% of the 207308580731477064 that Mezo's Router quoted when asked directly, before the click. The harvest used 657,449 gas.

### #411, from the keeper: refused, nothing sent

The keeper's dry run at 13:49 UTC and its live run at 13:52 UTC both simulated the #411 harvest first, and both simulations were refused with the Router's `InsufficientOutputAmount`, so no transaction was sent. The keeper wallet's nonce stayed at 10, and `owedOf(411)` stayed at 10026044170154743785.

The reason is the 0.0000118 BTC #411 also earned. PayDown sells BTC only at or above the oracle price less 1%. At the oracle's 79,729.69 MUSD that BTC is worth 0.9437 MUSD, so the floor is 0.9343 MUSD. Mezo's BTC/MUSD testnet pool would pay 0.9301 MUSD, about 1.44% under the oracle. The floor held, and no BTC was sold below it.

A harvest is one transaction, so the refused BTC sale also held back the 1.3838 MUSD. A read-only simulation of the same claim without the BTC returns 1.3838 MUSD. Nothing is lost: #411's rewards stay in Mezo's reward contracts until a harvest claims them.

### #411 again, from the keeper: the MUSD repaid, the BTC left waiting

The keeper now answers that refusal by running the same harvest with BTC left out of the claim. PayDown's 1% floor stayed as it was, and no contract changed.

| Step | Transaction |
| --- | --- |
| `harvest` on #411 with BTC left out: claim 1.3838 MUSD, repay 1.3838 MUSD | [0x2cece014...](https://explorer.test.mezo.org/tx/0x2cece0148e9f79c5c937800563bfda4deb67c4b9519f98425d70d9b919e4f9e2) |

The keeper's live run simulated the full claim first, and the Router refused it again. The keeper then simulated the same claim with BTC removed, which returned 1.3838 MUSD, and sent that. It landed in block 16590586 at 14:29 UTC, and the keeper logged:

```
31611-wave2 harvest 411 sent without BTC: Mezo's pool pays below the oracle floor (InsufficientOutputAmount()); repays 1.383819842227073913 MUSD, 0.000011836629687452 BTC waits for a later harvest | 0x2cece0148e9f79c5c937800563bfda4deb67c4b9519f98425d70d9b919e4f9e2
```

PayDown's `Harvested` event shows the keeper as caller, 1383819842227073913 MUSD repaid and no BTC sold. `owedOf(411)` fell by exactly that amount, from 10026044170154743785 to 8642224327927669872. The borrower's MUSD balance did not change, and PayDown holds no MUSD afterwards. The BTC stayed where it was: `earned(BTC, 411)` on the mcbBTC/BTC incentive contract read 11836629687452 before and after, so a later harvest can still claim it. The keeper lists only MUSD and BTC, so the 0.0268 mT is still claimable too. The harvest used 270,922 gas, and at 146 wei per gas the keeper paid 39,554,612 wei of test BTC. Its nonce went from 10 to 11.

It was close. The pool pays 0.9301 MUSD for that BTC, which meets the floor only while the oracle is at or below about 79,374 MUSD, and the oracle crossed that figure several times between 14:14 and 14:30 UTC. Keeper dry runs at 14:14 and 14:27 UTC simulated the full claim and it passed; the live run at 14:29 UTC was refused. A check a few minutes later found the pool back above the floor, 0.9301 MUSD against 0.9299, and the website's quote for the BTC alone read 0.9301 MUSD with `withoutBtc` false. Every run and every quote tries the full claim first, so which harvest goes out is decided by the price at that moment.

Before the send, the website's `quoteHarvest` for #411 returned 1.3838 MUSD with `withoutBtc` true, and its estimate read "Claiming now would repay about 1.3838 MUSD. BTC rewards wait until Mezo's pool pays within 1% of the price." The same quote for "Pay down and sell", as the borrower with the mT sale in it, returned 1.5913 MUSD with `withoutBtc` true. Both came from `packages/web/scripts/check-paydown.ts`, a read-only dry run. Nobody pressed either button.

Two more paths were proven on an anvil fork of Mezo testnet, not live. With the price feed set to revert, the keeper went straight to the claim without BTC and sent it, and `owedOf(411)` on the fork fell by the same 1383819842227073913. With PayDown's `harvest` forced to revert with an error nobody knows, every other job ran and the keeper exited with code 4.

What this page does not prove yet: a BTC sale through PayDown, since no harvest has sold any, and PayDown's own `BelowFloor` refusal, which has not fired live because the Router refuses first.

## How to check it yourself

```bash
cast call 0xB63fcCd03521Cf21907627bd7fA465C129479231 "ownerOf(uint256)(address)" 411 --rpc-url https://rpc.test.mezo.org
cast call 0x89Dc7C4a7Cbfddf3Cb7a00b5f3fEFaB47aC61a1f "isInVault(uint256)(bool)" 2 --rpc-url https://rpc.test.mezo.org
cd packages/contracts && bash script/verify-testnet.sh deployments/31611-wave2.json
```

The setup script is `packages/contracts/script/wave2-live.sh`. It records every transaction it sends, so running it again after a failure never sends anything twice.

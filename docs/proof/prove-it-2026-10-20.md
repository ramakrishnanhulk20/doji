# Prove-it run on Mezo testnet, 2026-10-20

One command, `bash packages/contracts/script/prove-it.sh`, run against the redeployed Doji contracts on Mezo testnet (code at commit 8a9b651, the fixes for the 2026-10-20 audit): LoanManager 0x983F2cD6e30492962104fc4dde8dbb5bd9d05Cfa, CreditMarkets 0x62cBa75f2fAA834ddCa4bF012258368D17Bbb2de, PassThrough 0x2E2430AB8Abbcbe89219dbB6D09265E10A5d2061. It locks a little test Bitcoin, borrows MUSD at a fixed rate, checks the result on chain, tries three attacks as a stranger, repays and takes the position back. Every transaction links to Mezo's explorer. The output below is unedited apart from removing the build tool's own progress lines.

The first run sent its borrow step (approve, then lockAndBorrow of position 391), but one of the nodes behind Mezo's public RPC answered null for the approve receipt, so the script read it as failed and stopped before the checks. The explorer shows that approve succeeded ([0x51afe055...](https://explorer.test.mezo.org/tx/0x51afe055ffb8f3154854c6bdfbfb3efac265263edfc68eeb2941f4711e3b22fa)), and the borrow is [0xe6cb9404...](https://explorer.test.mezo.org/tx/0xe6cb940454e61f45740a89ab14bb949ceda51a030cdae14ac771a7b4b6eb7813) in block 16261159. The script now asks again for a receipt the node left out (up to 15 times) before it counts a transaction as failed, and the proof was finished on the same position with its own resume option, `--resume 391 16261159`.
